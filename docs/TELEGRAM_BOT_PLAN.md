# План: Telegram-бот «Магазин в кармане»

**Статус:** планирование, 2026-08-07. Реализация не начата.
**Связанные документы:** `HANDOFF.md` §3.15 (per-store логика в едином боте), §3.17+ (Автосборка), `docs/STRUCTURE.md`.

---

## 1. Задача одним абзацем

Сотрудник/владелец магазина ещё до прихода на работу открывает Telegram и за 3 тапа:
включает автосборку заказов, скачивает всю накопившуюся печать одной пачкой, видит что
происходит в магазине и отвечает клиентам. Магазинов может быть несколько, у каждого свои
люди и свои права.

---

## 2. Что уже готово и переиспользуется целиком

| Компонент | Где | Состояние |
|---|---|---|
| Telegram-бот (aiogram 3, polling) | `backend/chatbot/bot_instance.py`, `worker.py::start_telegram_bot_polling` | Работает, единый `TG_BOT_TOKEN` на всё приложение |
| Print-Batcher (ZIP/PDF → пачки под принтер) | `backend/services/print_batcher_service.py`, хэндлеры в `chatbot/handlers.py` | Работает в боте: 4/8/9-на-A4, термо 75×120 и 100×150, авто-категории, дедупликация «уже печатали сегодня» |
| Автосборка (то, что пользователь называет «автопечать») | `backend/routers/auto_assembly.py`, `services/auto_assembly_{worker,engine}.py` | Работает: правила по 6 видам доставки, стадии `accept`/`assemble`/`waybill`, `dry_run`, расписание, лимит цены, чёрный список SKU, лимит на цикл |
| Спул накопленных накладных | `WaybillSpoolDB`, `GET /api/auto-assembly/spool`, `POST /spool/download`, `POST /spool/mark-printed` | Работает, per-store. **Доступен только из веба** |
| Уведомления в TG | `chatbot/notifications.py` (`notify_manager_and_block`, `notify_cookie_expired`) | Работают, уже показывают имя магазина |
| Роли пользователей | `UserStore.role` — `OWNER` / `MANAGER` / `VIEWER` | Есть в схеме, в боте не используется |

**Вывод:** ~70% бэкенда уже написано. Основная работа — идентификация, доставка этих
возможностей в интерфейс бота и уведомления.

---

## 3. Принятые решения

1. **Автопечать = серверная автосборка.** Физического агента печати на ПК магазина в этой
   итерации нет. Бот управляет правилами Автосборки и отдаёт готовые PDF-пачки в чат;
   человек печатает их по приходу. *(API проектируем так, чтобы агент печати мог
   подключиться позже без переделки — см. §8.)*
2. **Идентификация — deep-link из кабинета.** Никакого ручного ввода числовых Telegram-ID.
3. **Роли: владелец / сотрудник.** Ложатся на существующий `UserStore.role`:
   `OWNER` → полный доступ, `MANAGER`/`VIEWER` → сотрудник.
4. **Уведомления трёх групп:** чаты клиентов, проблемы магазина, деньги и заказы.
5. **Бот остаётся единым** на всё приложение (один токен). Мультитенантность решается
   привязкой, а не отдельными ботами.

## 4. Идентификация: модель данных и поток

### 4.1. Новые таблицы

```
telegram_links
  tg_user_id      BigInteger  PK      -- Telegram ID может превышать 2^31, только BigInteger
  user_id         FK users            -- к КОМУ привязан
  active_store_id FK stores  NULL     -- какой магазин выбран сейчас (если у user'а их несколько)
  tg_username     String     NULL     -- для отображения и аудита, может меняться
  tg_first_name   String     NULL
  linked_at       DateTime
  last_seen_at    DateTime

telegram_link_tokens
  token        String(43) PK          -- secrets.token_urlsafe(32); ≤64 символа = лимит deep-link payload
  user_id      FK users     NULL      -- NULL для приглашения нового сотрудника
  store_id     FK stores              -- к какому магазину привязываем
  invite_role  String       NULL      -- 'MANAGER'/'VIEWER' для приглашений; NULL = привязка себя
  created_by   FK users               -- кто выпустил (для аудита)
  expires_at   DateTime               -- TTL 15 минут
  used_at      DateTime   NULL        -- одноразовость
  max_uses     Integer     default 1  -- >1 для «пригласить 3 продавцов одной ссылкой»
  used_count   Integer     default 0

telegram_notification_prefs
  tg_user_id   BigInteger  PK, FK telegram_links
  store_id     FK stores   PK
  chats        Boolean  default true
  problems     Boolean  default true
  money        Boolean  default false   -- по умолчанию выкл: самый спамный канал
  new_order_min_sum  Integer NULL       -- порог суммы для уведомления о новом заказе
  quiet_from   Time  NULL   -- тихие часы, напр. 23:00
  quiet_to     Time  NULL   --             напр. 08:00
```

Права **не дублируем** — читаем `UserStore.role` по паре (`user_id`, `store_id`).

### 4.2. Поток «владелец привязывает себя»

1. Кабинет → Настройки → Telegram → кнопка «Привязать Telegram».
2. `POST /api/v1/telegram/link-token` (JWT + `X-Store-Id`) → создаёт токен, TTL 15 мин.
3. Фронт показывает **QR-код** и кнопку-ссылку `https://t.me/<bot>?start=<token>`.
   QR — потому что кабинет обычно открыт на компьютере, а Telegram на телефоне.
4. Пользователь жмёт → Telegram открывает бота → бот получает `/start <token>`.
5. Бот валидирует: токен существует, не истёк, `used_count < max_uses`. Создаёт
   `telegram_links`, помечает токен использованным, отвечает приветствием с именем магазина.
6. Кабинет по WebSocket/поллингу показывает «✅ Привязан @username».

### 4.3. Поток «владелец приглашает сотрудника»

Ключевое: **у сотрудника нет и не должно быть аккаунта в веб-кабинете.**

1. Владелец → Настройки → Telegram → «Пригласить сотрудника» → выбирает роль и срок.
2. Генерится токен с `user_id = NULL`, `invite_role = 'MANAGER'`, `max_uses` по желанию.
3. Владелец пересылает ссылку сотруднику в Telegram.
4. Сотрудник жмёт → бот создаёт **User без пароля** (флаг `is_telegram_only`, вход в веб
   невозможен) + строку `UserStore(user_id, store_id, role=invite_role)` + `telegram_links`.
5. Владельцу приходит уведомление: «👤 Иван (@ivan) присоединился к магазину Barkhan как
   сотрудник». Отвязать можно в кабинете одной кнопкой.

### 4.4. Безопасность

- Токен одноразовый (или с явным `max_uses`), TTL 15 минут, `secrets.token_urlsafe(32)`.
- **Deny by default:** непривязанный Telegram-ID видит только текст «Вы не привязаны ни к
  одному магазину, попросите владельца прислать ссылку». Никаких данных.
- Каждое действие из бота, меняющее состояние (вкл/выкл автосборку, правила), пишется в
  `AutoAssemblyLogDB`/аудит с пометкой «через Telegram, @username».
- Отвязка: `/unlink` в боте и кнопка в кабинете. Владелец может отвязать любого сотрудника.
- Проверка роли на каждое действие, не только при показе кнопок (кнопку можно нажать
  повторно после понижения роли — inline-клавиатура остаётся в истории чата).
- **Легаси-совместимость:** текущий механизм `ChatbotSettingsDB.admin_ids` остаётся
  фоллбеком, пока владелец единственного реального магазина не привяжется по-новому.
  Ломать работающий прод не нужно.

## 5. Интерфейс бота

### 5.1. Главный экран

Persistent reply-keyboard (всегда под полем ввода, не теряется в истории):

```
🏪 Barkhan                    ← шапка сообщения; /switch если магазинов >1

[ ☀️ Утренний сбор ]
[ 🖨 Печать (12) ]  [ ⚙️ Автосборка ]
[ 💬 Чаты (2) ]     [ 📊 Магазин ]
```

Цифры в кнопках — живые счётчики (обновляются при каждом рендере меню).

### 5.2. ☀️ Утренний сбор — главная фича

Одна кнопка, закрывающая исходный сценарий «еду на работу, хочу чтобы к приходу всё было
готово»:

1. Включает автосборку по всем правилам, где `enabled=false` (спрашивает подтверждение,
   показывает какие именно виды доставки включит).
2. Запускает `run_auto_assembly_cycle` немедленно, не дожидаясь 30-секундного тика.
3. Ждёт завершения, показывая прогресс («Принято 8 заказов, собрано 8, получено 8 накладных»).
4. Склеивает спул в пачку в формате по умолчанию магазина и присылает PDF прямо в чат.
5. Спрашивает: «Пометить как напечатанные?» → `mark-printed`.

Доступно только `OWNER` (шаг 1 меняет правила). Для сотрудника кнопка делает шаги 3–5 без
включения правил.

### 5.3. 🖨 Печать

- «Накоплено: 12 накладных» + список кодов заказов (свернуть, если > 20).
- [Скачать пачку] → формат по умолчанию, [Формат ▾] → выбор раскладки (переиспользуем
  существующую `get_layout_keyboard`).
- [Пометить напечатанными] → `mark-printed`.
- Приём ZIP/PDF вручную — как сейчас, но **с привязкой к активному магазину**.

### 5.4. ⚙️ Автосборка

Карточка на каждый из 6 видов доставки:

```
📦 Express        🟢 ВКЛ   (тест-режим)
   принять ✅ · собрать ✅ · накладная ✅
   [Выключить] [Настроить]
```

«Настроить» → стадии, `dry_run`, лимит цены, лимит на цикл. Расписание и чёрный список SKU —
только в вебе (в боте это неудобно редактировать, даём ссылку в кабинет).
Изменения — только `OWNER`.

### 5.5. 💬 Чаты

Уже частично есть (`notify_manager_and_block` + кнопка разблокировки). Добавить:
список активных диалогов, ответ прямо из Telegram (reply → уходит клиенту в Kaspi-чат),
кнопка «Передать ИИ обратно».

### 5.6. 📊 Магазин

Статус сессии Kaspi, заказы и выручка за сегодня, сколько заказов ждут сборки, состояние
демпинга, последние ошибки. Только чтение.

### 5.7. Мультимагазинность

`/switch` → список магазинов пользователя → выбранный пишется в
`telegram_links.active_store_id`. Имя магазина в шапке каждого экрана, чтобы нельзя было
случайно нажать «выключить автосборку» не в том магазине.

## 6. Уведомления

| Группа | События | По умолчанию |
|---|---|---|
| 💬 Чаты | Клиент написал; ИИ не справился и нужен человек | вкл |
| 🚨 Проблемы | Сессия Kaspi протухла; автосборка упала с ошибкой; Kaspi отдаёт ошибки; товар кончился на складе; радар конкурентов не отвечает | вкл |
| 💰 Деньги и заказы | Новый заказ (с порогом суммы); **Express-заказ — отдельно и всегда срочно**; вечерняя сводка за день; демпинг подвинул цену | выкл |

Правила доставки:
- **Тихие часы** (напр. 23:00–08:00) — накапливаем и шлём одним дайджестом утром.
  Исключение: Express-заказы и «сессия протухла» — приходят всегда.
- **Батчинг:** 5 заказов за минуту → одно сообщение, а не пять. Telegram ограничивает
  ~1 сообщение/сек в один чат.
- **Дедупликация:** «сессия протухла» не повторяется, пока не починена (механизм уже есть —
  `_cookie_alert_sent` per-store).
- Настройки — в боте (`⚙️ Уведомления`), персонально на каждого человека и каждый магазин.

*Не выбрано пользователем, но стоит держать в голове:* уведомление «накопилось N накладных к
печати» — естественно ложится в эту же схему, можно добавить выключенным по умолчанию.

## 7. Технические риски, которые надо закрыть по дороге

1. **🔴 Блокировка event loop.** `process_zip_or_pdfs` (PyMuPDF) — синхронная CPU-тяжёлая
   функция, вызывается прямо в async-хэндлере бота. Пока склеивается большой архив, **висит
   весь кабинет** — бот и FastAPI живут в одном процессе. Это баг уже сегодня, не только
   в новой фиче. Лечится `asyncio.to_thread`. Сделать в первую очередь.
2. **🔴 Печать в боте не знает про магазин.** `handlers.py` зовёт `load_printed_history()`,
   `reset_printed_history()`, `load_print_settings()` **без `store_id`** — история и
   настройки печати общие на всех тенантов. При втором клиенте — немедленный баг.
   `print_settings.json` надо перенести в БД per-store.
3. **🟡 Лимит 50 МБ на файл** в Bot API. Пачка на сотню термо-накладных может пробить.
   Решение: если >45 МБ — резать на части по N страниц; всегда предлагать альтернативу
   «скачать в браузере» по одноразовой ссылке.
4. **🟡 Один polling на процесс.** Два инстанса приложения = конфликт `getUpdates`.
   При масштабировании — выносить бота в отдельный процесс или переходить на webhook.
5. **🟡 `PENDING_FILES`** — in-memory dict, теряется при рестарте. Терпимо, но пользователь
   получит «файл истёк» без объяснений. Добавить внятное сообщение.
6. **🟢 Локализация.** В `config.py` уже есть ru/kk для чат-триггеров. Интерфейс бота
   логично сразу делать двуязычным — язык брать из `telegram_links` (Telegram отдаёт
   `language_code`), с переключателем.

## 8. Задел под агент печати (на будущее, не сейчас)

Чтобы физическая автопечать подключилась позже без переделки:
- пачку отдавать не только файлом в чат, но и через эндпоинт с одноразовым токеном
  (`GET /api/print-jobs/{id}/file?token=...`) — агенту он и понадобится;
- завести понятие «печатное задание» со статусом (`created` → `delivered` → `printed`),
  а `mark-printed` сделать одним из способов перевести его в `printed`;
- тогда агент = отдельный маленький клиент, который поллит задания и шлёт на принтер, а
  весь остальной код не меняется.
