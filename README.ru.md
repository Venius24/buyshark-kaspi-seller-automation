# BuyShark — автоматизация продавца Kaspi.kz

*[English version](README.md)*

SaaS для продавцов маркетплейса [Kaspi.kz](https://kaspi.kz): демпинг цен с защитой от ошибок,
детект чужих ботов, сборка и пакетная печать накладных, чат с покупателями с LLM-автоответчиком,
аналитика и финансы магазина. Работал в продакшене на реальных магазинах с июля по октябрь 2026.

> Бизнес закрыт, код открыт как портфолио. Ниже честно о том, что получилось, что сломалось
> и почему продукт не нашёл рынок.

## В цифрах

- **~3 месяца**, июль → октябрь 2026, история коммитов сохранена
- **~83 000 строк**: backend ~40k (Python), frontend ~22k (TypeScript), тесты ~22k
- **1375 тестов** в публичной версии, гоняются в CI
- один разработчик + AI-агенты (Claude Code)

Схема архитектуры и таблица модулей — в [английском README](README.md#architecture).

## Постмортемы

- **Тестовый прайс-лист на 2 SKU снял с продажи ~800 офферов.** Для Kaspi XML-прайс — это полный
  каталог, всё, чего в файле нет, снимается. Офферы восстанавливали вручную ночью. После этого у
  пайплайна фида появились снапшоты, guard и откат, а сам фид был выключен, пока выкатка не стала
  безопасной.
- **Самовывоз не существовал как класс.** У постамата и самовывоза одинаковый `deliveryMode`
  (`DELIVERY_PICKUP`), различитель — `isKaspiDelivery`. Все самовывозы считались постаматами, пока
  счёт не сверили с кабинетом владельца.
- **WAF Kaspi заблокировал IP сервера.** Скорее всего, хватило повторных чтений одних и тех же
  публичных страниц товаров с IP дата-центра. С этого момента продукт не мог работать надёжно —
  одна из причин его остановить.
- **Деплой молча откатывался.** `deploy.sh` откатывается при провале health-check, а `git log` на
  сервере продолжает показывать новый коммит. Источником правды стал `.last_good_sha`.
- **SKU с табами и пробелами не переживают прайс-лист** — Kaspi нормализует их и архивирует оффер.

## Почему не взлетело

Продукт работал, а рынок оказался занят: почти все активные продавцы к запуску уже сидели на
чужих демп-ботах. Единственный свободный сегмент — новички без бота; последняя рассылка на 30
новичков с персональным КП от 1000 ₸ дала 0 конверсий. Плюс системный риск: ключевые интеграции
держатся на неофициальных интерфейсах, которые Kaspi может поменять в любой момент.

## Что не опубликовано

Часть модулей в этом репозитории и во всей его истории заменена заглушками с тем же интерфейсом
(помечены `WITHHELD`):

- **Автоматизация входа в кабинет продавца Kaspi** — вход по email/паролю и одноразовому коду,
  вход по телефону и SMS для чата, подключение магазина в один клик с созданием сотрудника.
- **Транспорт радара цен** — как собирались предложения конкурентов с публичных страниц Kaspi
  несмотря на защиту от ботов. Интерфейс радара на месте, здесь он возвращает пустой рынок, и
  движок никогда не двигает цену.
- **Показатели качества продавца** — читались из внутреннего GraphQL кабинета.

Я не публикую код, назначение которого — обходить защиту чужой платформы. Логика вокруг этих
модулей открыта; полный код могу показать на созвоне.

## Запуск

```bash
python -m venv venv && venv/bin/pip install -r requirements-dev.txt
pytest tests/                      # 1375 тестов, без внешних сервисов
cd frontend && bun install && bun run dev
```

Бэкенд: `start.sh` / `start.bat`; без `DATABASE_URL` поднимается на локальной SQLite.
Для реальной работы нужен токен Kaspi Shop API.

## Важно

Проект не аффилирован с Kaspi.kz. Данные клиентов в истории обезличены: названия магазинов, SKU,
идентификаторы продавцов и товаров заменены на вымышленные («Бархан» — не настоящий магазин).
