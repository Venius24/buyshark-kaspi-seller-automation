# Assistant evals

Локальный запуск из корня репозитория:

```powershell
python -m evals.run
```

`cases.jsonl` содержит вход (`input`), сценарий ответов провайдера (`scenario`),
ожидаемую упорядоченную траекторию (`expected_tools`) и проверки (`invariants`).

Детерминированный режим использует `ScriptedProvider`, реальные engine/tools,
фикстуры загрузчиков и новую временную SQLite для каждого кейса. `.env` не
читается, сеть блокируется. Проверяются цикл, порядок инструментов, проверка
аргументов, изоляция store_id, лимит итераций, unavailable, запреты записи и
применения цены. Каталог должен остаться прежним; новые предложения могут быть
только pending. Пустой поиск проверяет отсутствие чисел в ответе, которых нет в
данных tools (простая проверка цифровых литералов, не семантическая оценка).
Кейс поиска по атрибуту использует остаток из каталожной фикстуры; поиск по
характеристикам проверенных карточек проверяется в `tests/test_assistant_rag_cards.py`.

**Это не оценка качества модели.** В детерминированном режиме модель не принимает
решений: tools и финальный текст заранее заданы. Проверка чисел подтверждает
работу проверяющего кода на сценариях, но не доказывает отсутствие галлюцинаций
реальной модели. Сценарий лимита сохраняет существующий финальный LLM-вызов без
tools и проверяет заглушку, когда этот вызов вернул ошибку.

Опционально, только при явно разрешённом доступе к сети:

```powershell
# ASSISTANT_API_KEY, ASSISTANT_PROVIDER, ASSISTANT_MODEL задаются в окружении
python -m evals.run --live
```

`--live` требует реальный провайдер и `ASSISTANT_API_KEY`, читает конфигурацию
только из окружения, оставляет данные фикстурами и БД временной. Сравнивает
**только выбранные моделью имена tools и их порядок** с `expected_tools`, отмечает
расхождения и ошибки провайдера; не оценивает качество текста или аргументов.
Сценарии злонамеренных аргументов/ошибок могут закономерно расходиться с реальной
моделью. Этот режим отправляет провайдеру синтетические данные и расходует токены.
